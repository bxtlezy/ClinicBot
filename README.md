# Поликлиника

Настольное приложение для записи пациентов на приём и работы сотрудников поликлиники. Интерфейс сделан на **PyQt6** с использованием **Qt Designer**, данные хранятся в **SQLite** через **SQLAlchemy**.

## Возможности

- Три роли: **пациент, врач и администратор**.
- Первый зарегистрированный аккаунт автоматически становится администратором.
- Запись к конкретному врачу с учётом его индивидуального расписания.
- Рабочие дни, часы приёма, длительность слота, перерыв, отпуск и отдельные выходные даты врача.
- История каждого приёма: создание, отмена, перенаправление, явка/неявка, заметки и оценка.
- Отдельная **карточка пациента** с историей обращений.
- Отдельная **карточка врача** с расписанием, статистикой и рейтингом.
- Отзывы, оценки, жалобы и модерация отзывов.
- Управление врачами и специальностями.
- Подбор специальности по описанию симптомов.
- Кликабельные карточки показателей на главном экране.
- Хеширование паролей, сохранение сессии через системное хранилище `keyring`.
- Монохромная иконка глаза прямо в поле пароля для показа/скрытия введённого пароля.

## Установка и запуск

В терминале из папки проекта:

```bash
python -m pip install -r requirements.txt
python main.py
```

При первом запуске папка `data/` и базы данных создаются автоматически.

**Первый зарегистрированный пользователь получает роль администратора.** Все следующие пользователи, зарегистрированные через обычную форму, получают роль пациента. Аккаунты врачей создаёт администратор.

Если проект запускается поверх старой версии, в которой роль называлась `registrator`, она автоматически переводится в `admin` при запуске. Старые записи сохраняются.

# Кнопки и элементы приложения

## Экран входа

| Элемент | Что делает |
| --- | --- |
| **Логин** | Поле для ввода логина пользователя. |
| **Пароль** | Поле для ввода пароля. По умолчанию символы скрыты. |
| **Иконка глаза** | Показывает пароль; повторное нажатие снова скрывает его. Глаз находится прямо внутри строки пароля. |
| **Запомнить вход на этом устройстве** | Сохраняет защищённый токен сессии через `keyring`, чтобы при следующем запуске не вводить пароль. |
| **Войти** | Проверяет логин и пароль и открывает кабинет пользователя. |
| **Зарегистрироваться** | Открывает форму создания нового аккаунта. |

## Экран регистрации

| Элемент | Что делает |
| --- | --- |
| **Логин** | Логин нового пользователя. Должен быть уникальным. |
| **Пароль** | Пароль не короче 8 символов. |
| **Иконка глаза** | Показывает или скрывает пароль прямо в строке ввода. Отдельной надписи «Показать пароль» больше нет. |
| **Сгенерировать надёжный пароль** | Создаёт случайный пароль из букв, цифр и специальных символов. После генерации пароль показывается, чтобы его можно было сохранить. |
| **Копировать** | Копирует пароль в буфер обмена. |
| **ФИО** | Имя пользователя, отображаемое в приложении. |
| **Телефон** | Номер автоматически форматируется как `+7 999 123-45-67`. |
| **Зарегистрироваться** | Проверяет поля и создаёт аккаунт. |
| **Назад** | Возвращает на экран входа без сохранения. |

Под каждым неверно заполненным полем показывается отдельная подсказка. Первый созданный аккаунт получает права **администратора**, остальные обычные регистрации создают **пациентов**.

# Обзор

На странице находятся четыре большие карточки. **Теперь они кликабельны.** При наведении курсор меняется, а карточка подсвечивается.

| Карточка | Что показывает | Что происходит при нажатии |
| --- | --- | --- |
| **Всего записей** | Количество доступных пользователю записей. | Открывает раздел «Записи на приём». |
| **Актуальные** | Активные и перенаправленные записи. | Открывает раздел «Записи на приём» и показывает только актуальные записи. |
| **На сегодня** | Записи на текущую дату. | Открывает раздел «Записи на приём» и показывает только записи на сегодня. |
| **Отзывы** | Количество доступных отзывов. | Открывает раздел «Отзывы». |

## Быстрые действия

| Кнопка | Кому доступна | Что делает |
| --- | --- | --- |
| **+ Записаться к врачу** | Пациент, администратор | Открывает форму новой записи. |
| **Моя карточка** | Пациент | Открывает собственную карточку пациента. |
| **Моя карточка** | Врач | Открывает собственную карточку врача. |

# Записи на приём

В таблице показываются:

- дата;
- время;
- пациент;
- специальность;
- врач;
- статус;
- жалобы.

Над таблицей находится **поиск**. Он ищет по пациенту, врачу, специальности, дате, времени и статусу.

Чтобы применить действие, сначала выделите строку в таблице.

## Кнопки раздела записей

| Кнопка | Кому доступна | Что делает |
| --- | --- | --- |
| **+ Записаться** | Пациент, администратор | Открывает форму создания записи. |
| **Отменить** | Пациент, администратор | После подтверждения переводит запись в статус «Отменена». Событие сохраняется в истории. |
| **Оценить врача** | Пациент | Позволяет поставить от 1 до 5 звёзд и написать отзыв после завершённого приёма. |
| **Отметить явку** | Врач | Предлагает «Пришёл» или «Не пришёл». «Пришёл» завершает приём, «Не пришёл» создаёт отдельный статус **«Неявка»**. |
| **Заметка** | Врач | Создаёт или изменяет заметку врача к выбранному приёму. Факт изменения попадает в историю. |
| **Перенаправить** | Врач | Выбирает другого врача и свободное время на ту же дату. Старый и новый врач/время сохраняются в истории. |
| **История** | Все роли, имеющие доступ к записи | Показывает хронологию всех сохранённых действий по приёму. |
| **Карточка пациента** | Врач, администратор | Открывает данные пациента и историю его обращений. Врач может открыть только пациента, с которым у него есть приём. |
| **Карточка врача** | Все роли | Открывает данные и статистику врача, указанного в выбранной записи. |

## Статусы приёма

| Статус | Значение |
| --- | --- |
| **Активна** | Обычная будущая или текущая запись. |
| **Перенаправлена** | Запись была переведена к другому врачу. |
| **Завершена** | Пациент пришёл, врач отметил приём завершённым. |
| **Неявка** | Пациент не пришёл. Это больше не считается отменой. |
| **Отменена** | Запись отменил пациент или администратор. |

# История приёма

Кнопка **История** открывает отдельное окно с колонками:

- дата и время события;
- кто выполнил действие;
- описание события.

Сохраняются следующие события:

- создание записи;
- отмена;
- перенаправление;
- явка;
- неявка;
- изменение заметки врача;
- оставленная оценка.

Для старых записей, созданных до появления журнала, приложение показывает сообщение, что ранняя история не была сохранена.

# Форма записи к врачу

| Элемент / кнопка | Что делает |
| --- | --- |
| **Пациент** | Администратор выбирает пациента из списка. У пациента поле автоматически заполнено его аккаунтом и недоступно для изменения. |
| **Жалобы** | Свободное описание причины обращения. |
| **Подобрать специальность по симптомам** | Ищет совпадения по ключевым словам и предлагает подходящую специальность. Это подсказка, а не диагноз. |
| **Специальность** | Фильтрует список врачей. |
| **Врач** | Выбирает конкретного врача. |
| **Календарь** | Выбирает дату в пределах ближайших 56 дней. |
| **Время** | Показывает только реально свободные слоты выбранного врача с учётом его графика, перерыва и выходных. |
| **Записаться** | Сохраняет запись и создаёт первое событие в её истории. |
| **Отмена** | Возвращает к списку записей без создания записи. |

# Карточка пациента

Карточка показывает:

- ФИО;
- логин;
- телефон;
- общее количество записей;
- количество завершённых приёмов;
- количество неявок;
- количество отмен;
- полную таблицу обращений.

В таблице карточки пациента видны дата, время, врач, специальность, статус, жалобы и заметка врача.

**Пациент** может открыть собственную карточку с главной страницы. **Врач** может открыть карточку пациента из выбранной записи. **Администратор** может открывать карточки пациентов из записей.

---

# Карточка врача

Карточка показывает:

- ФИО;
- специальность;
- телефон;
- рабочее расписание;
- общее число записей;
- предстоящие записи;
- завершённые приёмы;
- среднюю оценку;
- количество отзывов.

Администратор и сам врач дополнительно видят список пациентов и приёмов. Пациент видит только общую информацию и статистику врача без списка чужих пациентов.

Раздел доступен **администратору**.

| --- | --- |

# Форма врача

| Элемент / кнопка | Что делает |
| --- | --- |
| **Логин** | Логин врача. При редактировании изменить его нельзя. |
| **Пароль** | При создании обязателен. При редактировании можно оставить пустым, чтобы не менять пароль. |
| **Иконка глаза** | Показывает или скрывает пароль внутри строки ввода. |
| **ФИО** | Имя врача. |
| **Телефон** | Контактный номер. |
| **Специальность** | Специальность врача. |
| **Сохранить** | Создаёт врача или сохраняет изменения. |

# Редактор расписания врача

Открывается кнопкой **Расписание** после выбора врача.

## Рабочие дни

Флажки **Пн, Вт, Ср, Чт, Пт, Сб, Вс** определяют дни недели, когда врач принимает пациентов.

## Время

| Элемент | Что делает |
| --- | --- |
| **Начало работы** | Время первого возможного приёма. |
| **Последняя запись** | Время последнего возможного начала приёма. |
| **Длительность приёма** | Интервал между слотами. |
| **Использовать перерыв** | Включает или отключает перерыв. |
| **Начало перерыва** | С какого времени новые слоты не предлагаются. |
| **Конец перерыва** | Когда запись снова становится доступной. |

## Выходные / отпуск

| Элемент / кнопка | Что делает |
| --- | --- |
| **Календарь** | Выбирает отдельную дату. |
| **+ Добавить дату** | Добавляет выбранный день в список выходных/отпуска. Запись к врачу в этот день становится недоступна. |
| **Убрать выбранную** | Удаляет выделенную дату из списка выходных. |
| **Сохранить** | Сохраняет рабочие дни, часы, длительность приёма и перерыв. |
| **Отмена** | Закрывает окно без изменения основной части расписания. Уже добавленные/удалённые даты выходных сохраняются сразу после соответствующей кнопки. |

# Безопасность и хранение данных

Пароли не сохраняются открытым текстом. Используется `PBKDF2-HMAC-SHA256` с индивидуальной солью и большим количеством итераций.

При включённом «Запомнить вход» в базе хранится только хеш случайного токена, а сам токен помещается в системное хранилище через `keyring`.

Для учебного/локального проекта данные пациентов хранятся в SQLite. Для реального применения с медицинскими данными дополнительно понадобятся шифрование базы, журнал доступа, резервное копирование, разграничение прав и требования законодательства о персональных данных.

# Структура проекта

```text
main.py             запуск приложения
gui.py              окна, диалоги и обработчики кнопок
service.py          авторизация и бизнес-логика
database.py         модели SQLAlchemy и подключение к SQLite
styles.qss          общие стили интерфейса
requirements.txt    зависимости
ui/                 формы Qt Designer (.ui)
data/               локальные базы данных
```

В папке `data/` создаются две базы:

- `accounts.db` — пользователи, роли, хеши паролей и сохранённые сессии;
- `clinic.db` — записи, история приёмов, расписания врачей, выходные даты, специальности и отзывы.

## Основные таблицы

- `users` — аккаунты;
- `sessions` — сохранённые входы;
- `appointments` — приёмы;
- `appointment_events` — история действий по приёмам;
- `doctor_schedules` — постоянное расписание врачей;
- `doctor_days_off` — отдельные выходные и отпуск;
- `reviews` — отзывы;
- `specializations` — специальности.

# Изменение интерфейса

Файлы из папки `ui/` можно открывать в **Qt Designer**. После изменения достаточно сохранить `.ui` и заново запустить приложение. Конвертация `.ui` в Python не нужна.

Некоторые новые элементы — монохромная иконка глаза в поле пароля, кнопки карточек, истории и расписания — создаются программно в `gui.py`, поэтому их не будет видно как отдельные элементы в Qt Designer.

При переименовании существующих элементов учитывайте их `objectName`, потому что `gui.py` обращается к ним по этим именам.

Не публикуйте личные файлы `*.db`, виртуальное окружение, `.idea/` и другие локальные данные. Для этого используйте `.gitignore`.
